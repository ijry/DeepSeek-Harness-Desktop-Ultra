# dsh-plugin-longread

把一本小说读成一场 dsh 会话：上面是一句你自己敲的需求，中间是几条工具调用，下面是一段正在流式输出的「回复」——那段回复其实是小说正文。远看是在 vibe coding，近看在看书。

支持导入 `.txt` 与 `.epub`，按章记住读到哪儿，内置一本原创示例小说《九阴真经》。**纯 GUI 插件：不注册任何工具、不改系统提示、agent 侧完全看不见它。** 可发布到 dsh 插件市场。

一个插件 = 两个半边：

- **host 半边**（`exports "."`）：导入与编码嗅探、书架账本、章节切分，以及把一章正文编排成「假会话」的计划生成器。计划在 host 算完再以 JSON 下发，所以这套逻辑只有一份实现、一套测试。
- **浏览器半边**（`exports "./client"`）：零依赖原生 DOM，一个单文件 IIFE。它只负责播：工具行从「运行中」翻成完成，然后正文一个字一个字打出来。

## 伪装是怎么搭起来的

一章正文被切成若干「轮」，每一轮长成一次真实的 agent 往返：

| 屏幕上的东西 | 实际是什么 |
| --- | --- |
| 顶上那句用户消息 | 你在输入框里敲的字（什么都不敲就用生成的那句） |
| `✳ 思考 3.4s` | 随机但可重放的一行 |
| `● read src/lib/retry.ts` + `(End of file - total 412 lines)` | 假的工具调用，工具名与结果串都是 dsh 真实工具的原话 |
| 正在打字的正文 | 小说 |
| `—— 上下文已压缩 · 继续 ——` | 换章 |
| 头部右侧的 `3/9 · 41% · 12:07 · 8.4k tokens` | 章号、进度、开面板到现在的时长、按字数折算的假 token 数 |
| 头部左侧的 `重构 · retry.ts` | 伪装身份 + 本轮引用的文件名。**书名不出现在任何一处 chrome 上** |

两个细节决定了它像不像：

**工具调用引用的是真文件。** host 会扫一遍你自己的 dsh 工作区（有界：深度 4 层、跳过 `node_modules`/`.git`/`dist`、最多 400 个文件、缓存 5 分钟），假的 `read` / `edit` / `grep` 从这个池子里取路径。屏幕上出现的是你这个项目里真实存在的文件。扫不到工作区就退回一份内置路径表——伪装降级，面板照用。

**同一章重开一次，伪装一模一样。** 计划由 `(bookId, 章号, 轮号, 伪装身份)` 做种子生成，不是每次随机。否则续读时前后文对不上，一眼就能看出是编的。

代价也写明：这些工具行是**假的**，它们不读文件、不跑命令、不写任何东西；展开来看到的参数与输出是编的。真要留证据的话，这个插件帮不上忙。

## 数据存在哪（两个去处，各有理由）

| 数据 | 存法 | 为什么 |
| --- | --- | --- |
| 书架、章节范围、每本书读到哪、阅读设置 | `<DSH 家目录>/dsh-plugin-longread.json` | 画菜单要读它，所以它必须小 |
| 每本书的正文 | `<DSH 家目录>/dsh-plugin-longread-books/<id>.txt` | 一本书几 MB；塞进账本就等于每次列书架都要解析一部小说 |

正文与账本是两次写，顺序固定：**先落正文，再提交账本行**。反过来会出现指向空文件的书。账本坏了就改名留档（`.corrupt-<时间戳>`），不会让插件起不来。

## 导入：txt 与 epub

- **txt**：BOM 优先，然后**严格** UTF-8，失败才退到 GB18030、Big5。中文小说有一半是 GB18030，猜错的结果是满屏乱码而不是报错，所以这里宁可多试一轮也不做有损解码。章节按 `第N章` / `第 12 回` / `卷三` / `楔子` / `Chapter 3` 这些行首形状切；一个标题都没有的文件按 2400 字切成「第 N 节」。
- **epub**：自己读 zip（`inflateRaw`，不引依赖），按 `container.xml` → OPF → spine 顺序取章，章名优先用 `toc.ncx`。整本塞成一个文档的坏 EPUB 会退回按标题切章。
- 导入走浏览器 FileReader 的 data URL 上传，**字节不在浏览器里解码**——编码嗅探只在 host 做一次。

拖一个文件到面板上，或者在书架里点「导入文件…」。

## 键盘与命令

面板打开时：

- `Enter` / `空格` / `→` 推进一轮；正在输出时再按一次跳到本段末尾
- `[` `]` 上一章 / 下一章
- `Esc` **收起面板**——也就是那个「老板键」，正在打的字立刻停住
- 输入框里敲什么都会变成那一轮的用户消息，所以随便敲

斜杠命令（在输入框里）：`/lib` 书架 · `/toc` 目录 · `/next` · `/prev` · `/goto N` · `/speed N`（字/秒，600 = 立即显示）· `/font N` · `/persona refactor|debug|review|docs` · `/density off|low|medium|high` · `/auto` · `/stop` · `/help`

## 可调的分寸

设置里能改：速度、每轮字数、字号、伪装身份（重构 / 排查 / 审阅 / 文档，各有自己的一套提示词与工具组合）、工具调用密度、思考块开关、自动播放、是否引用真实路径。带「下一章生效」标记的项要切章后应用——因为计划是整章一次算好的。

**支持暗黑模式**：颜色全部取自外壳自己的主题变量（`--dsw-alias-*`），跟着 dsh 一起亮暗，没有第二套配色需要维护。

## 内置的《九阴真经》

一部**为这个插件原创**的武侠中篇，九章，约 1.5 万字，随本包以 MIT 许可发布。除了「九阴真经」这个题目概念，人物、情节、文句全部原创，与任何已有作品无关。

它不是特例数据：种进书架时走的是和导入 txt 完全相同的 `normalizeText` + 章节切分，所以它同时是那条链路的夹具。第一次打开面板才会写进你的 DSH 家目录；删掉之后不会自己长回来。

## 已实现 / 尚未实现

已实现：txt/epub 导入、书架与删除、目录跳转、按轮记进度与续读（把已读的最后几轮瞬间补回来）、四种伪装身份、真实路径池、暗黑模式、老板键。

**尚未实现**（明写出来）：

- 不认 `.mobi` / `.azw3` / PDF，也不解密 DRM。
- epub 只取文字：图片、样式、脚注、目录层级一概丢掉。
- 没有搜索、书签、批注、字体族切换。
- 竖排与繁简转换都没有。
- 进度只按「章 + 轮」记，改了「每轮字数」之后，续读的位置会偏。

## 开发与验证

零运行时依赖，无需 `npm install`：

```bash
npm run check    # 语法检查 src/ → 重新构建 lib/ → 再查 lib/（含生成的 client 包）
npm run build    # 复制 host/shared 到 lib/ 并生成 lib/client.js
npm test         # npm run build && node --test
```

测试里有一份手写 DOM 替身（`test/dom-stub.mjs`），`test/client.test.mjs` 把打好的 bundle 塞进去真跑一遍：座位挂载、工具行翻状态、正文逐段出现、Esc 收摊、dispose 收干净。这是唯一能验证「读起来像一场会话」的地方。

## 安装到 dsh

```bash
# 本仓库开发时
dsh plugin --profile <profile> add link:plugins/dsh-plugin-longread

# 发布到 npm 后按包名安装
dsh plugin --profile <profile> add dsh-plugin-longread
```

重启 `dsh web` 后侧栏出现「长文」入口。

## 安全须知

- **不开监听端口、不发任何出站请求。** 路由挂在 dsh 自己的 web 服务上，和 GUI 同源。
- 导入的书**明文**存在你的 DSH 家目录下，没有加密。同一台机器上能读你家目录的人就能读这些书。
- 它对 agent 完全透明：不注册工具、不加系统提示段落、不写会话日志。`test/entry.test.mjs` 里的 ctx 替身在 `ctx.tools` 与 `ctx.systemPrompt` 上装了地雷——谁顺手加个工具，测试就红。
- 老板键只是收起面板，**不清屏、不擦历史**：面板再打开还在原处。
